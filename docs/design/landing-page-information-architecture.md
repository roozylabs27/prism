# Landing Page Information Architecture

Primary buyer: AI automation agencies (5 to 30 clients). Secondary: platform teams.
Approved 2026-11-19.

| # | Section | Job | Structure |
|---|---|---|---|
| 0 | Header | Orient, reach CTA | Logo, anchors (Product, Agencies, Integrate, Status), Docs, GitHub, primary CTA, theme toggle |
| 1 | Hero | State what Prism is in one line | Headline, sub-line, two CTAs, request-path diagram |
| 2 | Boundary | Say what Prism governs and what it does not | Two-column list plus MCP boundary diagram |
| 3 | Agencies | Map shipped features to agency pain | Table: problem, what Prism does, where it lives |
| 4 | Inference control | Routing, failover, credentials, budgets | Prose blocks with endpoint and header references |
| 5 | Agent control | Agent identity, allowlists, MCP gateway, audit | Definition list plus a short policy example |
| 6 | Integrate | Get running | Tabs: Python, TypeScript, cURL, Claude Code (MCP), Claude Desktop (MCP) |
| 7 | What ships today | Credibility through honest status | Table: Shipped / In progress |
| 8 | Ways to start | Convert | Two options: self-host, design-partner pilot |
| 9 | Footer | Links | Repository, docs, changelog, issues |

## Removed

Stats banner, routing simulator, failover costume, budget mockup, versioned provider grid, background canvas, four-tier pricing.

## Copy rules

- Every capability links to a real endpoint, header or document.
- No numbers without a cited source on the page.
- No em dashes in UI copy.
